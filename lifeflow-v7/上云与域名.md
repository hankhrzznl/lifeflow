## 二、上 Vercel（纯浏览器，不需要 CLI 登录）

1. 打开 **https://vercel.com/new**
2. **Import Git Repository** → 选 `hankhrzznl/lifeflow` → **Import**
3. ⚠ **Root Directory 改成 `lifeflow-v7`**
   —— 仓库根是旧的 v2 工程（用的是 Tailwind v4 + serwist 那一套），
   不改这一项 Vercel 会去构建它，而不是新工程。
4. Framework Preset 会自动是 **Next.js**，其它不用动
5. **Deploy**
6. 拿到 `https://<项目名>.vercel.app`

**之后**：往 `main` 推代码 = 自动部署。

## 三、挂自己的域名

1. Vercel 项目 → **Settings → Domains** → 填你的域名 → **Add**
2. Vercel 会给出 DNS 记录，两种常见情形：
   - **根域**（如 `lifeflow.com`）→ 加 **A 记录** 指向 Vercel 给的 IP
   - **子域**（如 `app.lifeflow.com`）→ 加 **CNAME** 指向 `cname.vercel-dns.com`
3. 去你的域名服务商照着加，等 DNS 生效（几分钟到几小时）
4. Vercel 自动签 HTTPS

⚠ **iPad 上部署后仍是「加到主屏」**：不管用 `.vercel.app` 还是你的域名，
未加主屏的网页 Safari 会在 7 天不活跃后清本地数据；加到主屏才豁免 ITP。

## 四、⚠️ 上域名之前必须知道的一件事

**部署到域名 ≠ 三设备共用数据。**

现在数据全在**各设备的浏览器本地**（IndexedDB）。部署后：

```
手机  -> 访问你的域名 -> 自己的一份数据
iPad  -> 访问同一个域名 -> 另一份数据
电脑  -> 访问同一个域名 -> 再一份数据
```

**三个网址相同，三份数据互不可见。**

这正好撞在你最早提的需求上 ——「要，一份数据」。
所以正确顺序是：

```
① 接跨设备同步（Supabase）  →  三台设备共用一份
② 再上域名                  →  在哪儿打开都是同一份
```

**反过来的话，只是把"三份数据"搬到了三个网址上** —— 问题一个没解。

需要你做的只有一步：去 [supabase.com](https://supabase.com) 建个项目（免费档够用），
把 **Project URL** 与 **anon public key** 给我，我就接上。
方案项目里已经写好：[`docs/17-多设备同步方案-Supabase.md`](../../docs/17-多设备同步方案-Supabase.md)
+ `PROMPTS-同步工程-Supabase/` 6 份执行提示词。
