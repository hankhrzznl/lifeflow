## 一、架构诊断：断点的结构性根源

走查发现的 8 个卡点（H1/H2/M1-M4/L1/L2），不是 8 个孤立 bug，而是 **4 个结构性断点** 的表征：

| 断点 | 本质 | 表层症状 |
|---|---|---|
| **B1 入口重复** | 同一个「模块」在习惯页、我的页、首页出现多个入口，用户分不清主入口 | M4（吃药两页冲突）、M2（训练入口断裂） |
| **B2 首页职责过重** | 首页想同时回答"现在做什么/今天长啥样/怎么加事/什么样式"，核心任务被淹没 | H1（首屏过载 + 样式预览泄漏）、L2（数字对不上） |
| **B3 冷启动承诺与能力错位** | 引导说"可改"，交互只兑现一部分 | H2（只有睡眠可改）、L1（30% 无依据） |
| **B4 意图↔执行↔回顾链路不闭环** | 建了目标/习惯，但"切出行动"和"回看推进"的路径是断的 | M1（挂靠命名乱）、M2（训练就近入口缺失）、M3（专注层级错） |

**一句话结论**：体验断点不是"页面没做好"，而是**入口没有唯一化、页面没有单一职责、链路没有闭环**。

## 二、核心设计原则（4 条，所有页面必须遵守）

**P1 单页单任务**：每个页面只回答一个问题。
- 今日安排 = 「现在该做什么」· 目标 = 「我要达成什么」· 习惯 = 「我要坚持什么」· 回顾 = 「我推进得怎样」· 我的 = 「去哪配置」

**P2 入口唯一化**：一个实体只有一个「主入口」，其余是"快捷/引用/配置"视图，不是重复入口。

**P3 意图→执行→回顾黄金闭环**：用户心智是「立意图（目标/习惯）→ 执行（今日安排）→ 看推进（回顾）」，任何一环断了，产品就散。

**P4 冷启动是状态迁移，不是常驻功能**：四步走完即进入日常，默认习惯是"预置种子"，引导只是"点亮+个性化"，两者单源。

## 三、信息架构：5 tab 职责边界（收敛版）

| tab | 核心任务 | 只放什么 | 不放什么 |
|---|---|---|---|
| **今日安排** | 现在做什么 + 今天长啥样 | 概览 · 现在 · 时间轴 · 当日格 · 收场 | 锁屏预览、图例（降级）、冗余工具入口 |
| **目标** | 有终点的意图 | 目标卡列表（挂靠维度做进度） | 推进工具（训练/记账已归我的页） |
| **习惯** | 无终点的意图 | 默认习惯 + 自定义习惯 + 可选模块 | 统计（连续天数/热力已归回顾页） |
| **回顾** | 推进得怎样 | 目标推进 + 习惯推进 + 专注 + 周报告 | 打卡热力（鸡肋已删） |
| **我的** | 去哪配置 | 工具 + 记录 + 系统 + 数据 | 模块使用入口（已归习惯页） |

## 四、模块入口策略（解决 B1，核心决策）

**决策：模块只有一个「主入口」——习惯页。** 其他入口降级为不同视图，不是重复。

| 入口 | 性质 | 场景 | 去留 |
|---|---|---|---|
| 习惯页「默认习惯段」 | **主入口**（模块=默认习惯） | 查看/管理我的睡眠习惯 | ✅ 保留 |
| 首页「当日格」 | 快捷打卡（只读 + 快速记） | 喝口水点一下 | ✅ 保留，但点进去跳习惯页 |
| 我的页「模块中心·身体养护」 | ~~重复入口~~ | — | ❌ **砍掉**（模块已在习惯页） |
| 我的页「工具组」 | 工具唯一入口 | 训练/记账（非习惯，是挂靠维度/记录工具） | ✅ 保留 |
| 目标页「挂靠标签」 | 引用（可点击直达） | 从目标跳到挂靠维度 | ✅ 改为可点击 |

**结果**：模块（睡眠/饮水/饮食/久坐/吃药/功法养生）只在习惯页出现一次；工具（训练/记账）只在我的页出现一次。彻底消除 M4 的双页冲突。

### 4.1 入口分布实证（2026-08-19 全量 grep）

| 模块 | 入口分布 | 判定 |
|---|---|---|
| 睡眠/饮水/饮食/久坐 | habit + more + review（饮水/久坐 + schedule 当日格） | 🔴 习惯页、我的页重复 |
| 吃药/功法养生 | habit（可选隐藏）+ more（身体养护） | 🔴 重复 |
| 训练 | **只在我的页**（+ training 子页） | ⚠️ 目标页挂靠却点不进 |
| 记账 | goals（挂靠）+ more + review | ⚠️ 三处散落 |
| 专注 | schedule（开始专注）+ review（统计） | ✅ 定位正确 |

### 4.2 砍「身体养护组」的 3 个边界条件（必须同步做）

> 决策「砍身体养护组」成立，理由两条：①它是无数据的死链接（纯图标+名，无进度条）；②它违背「模块=默认习惯」定位。但砍掉必须连带以下 3 条，否则治标不治本。

1. **「模块中心」改名为「工具」**：砍掉身体养护后只剩训练/记账，`模块中心` 标题名不副实，改 `工具`。
2. **同步优化习惯页可选模块的开启入口**：吃药/功法养生现在是 `is-hidden`、靠页底语义模糊的「管理格子」按钮展开。若只砍我的页入口不优化此处，等于把吃药从"两处难找"变"一处难找"。需让"开启吃药"在习惯页清晰可发现。
3. **训练/记账保留在「工具」组，且目标页挂靠标签必须可点击直达**：否则 M2（减脂目标"下一步去训练"点不进）仍断。

### 4.3 训练「孤岛」问题（比 M2 更深）

训练入口现在只在我的页（+ training-big3/training-plan 子页），从目标页、回顾页、首页都无路径到训练。记账三处散落（goals/more/review）。**训练被隔离在「我的页孤岛」，需通过条件 3 打通挂靠标签直达。**

## 五、完整用户旅程

### 阶段 0 · 冷启动（一次性状态迁移）
```
首开 → ①确认默认习惯（4个预置，全部可改默认值）
    → ②种一个习惯（可选）
    → ③立一个目标（可选，选挂靠维度）
    → ④点亮今天（预览"今日安排"成形）
    → 进入今日安排（首页已满）
```
- ②③ 可选、可跳过；① 默认习惯即使跳过也在（P4 单源）。
- ④ 的预览必须和跳转后的首页一致（消除 L1 的"30% 无依据"——改成定性描述，或给出明确构成）。

### 阶段 1 · 日常循环（核心闭环，P3）
```
早上：首页「现在」→ 执行（专注/打卡/完成）
白天：有动作 → 打卡（习惯页/首页当日格）→ 记进度
晚上：今日收场 → 结束今天
每周：回顾页 → 看目标/习惯推进 → 得到下一步
```

### 阶段 2 · 成长循环（意图演进）
```
回顾发现目标落后 → 回目标页调整（暂停/完成/改挂靠）
回顾发现习惯断了 → 回习惯页重启（重新充能）
```
- 关键：回顾页的「下一步」必须可点击，直接跳回意图页（解决 M2 的训练就近入口 + 闭环）。

## 六、页面流转地图

```
                    ┌─────────── 冷启动 onboarding ───────────┐
                    │  ①默认 ②习惯 ③目标 ④点亮                │
                    └──────────────────┬──────────────────────┘
                                       ▼
        ┌────────────────────── 今日安排（首页）─────────────────────┐
        │  概览 → 现在 → 时间轴 → 当日格 → 收场                     │
        │    │        │          │                                  │
        │    ▼        ▼          ▼                                  │
        │  专注   目标切片    打卡(习惯/模块)                        │
        └─────┬────────────┬──────────────┬──────────────┬─────────┘
              ▼            ▼              ▼              ▼
         目标(有终点)   习惯(无终点)    回顾(推进)      我的(配置)
              │            │              │              │
              └──挂靠──► 模块(睡眠..) ◄── 下一步 ◄── 回顾 │
              │                          ▲               │
              └──────────────────────────┘        工具(训练/记账)
```

**闭环路径**（重点打通）：
1. 目标页「挂靠训练」→ 点击直达训练（解决 M2）
2. 回顾页「下一步：今日训练 1 次」→ 点击直达训练（解决 M2）
3. 回顾页「习惯推进」卡 → 点击回习惯页（解决习惯断签后重启）
4. 首页「当日格」→ 点击进习惯页（统一主入口）

## 七、断点修复映射（8 卡点 → 架构方案）

| 卡点 | 架构方案 | 优先级 |
|---|---|---|
| H1 首页过载+样式泄漏 | 删锁屏预览；首页收敛为「概览→现在→时间轴→当日格→收场」（P1） | 🔴 P0 |
| H2 冷启动只睡眠可改 | 4 默认习惯全部可改默认值（P4 个性化） | 🔴 P0 |
| M1 挂靠命名不一致 | 统一为纯维度名（训练/睡眠/记账/阅读），去掉「阅读习惯」自指 | 🟡 P1 |
| M2 训练入口断裂 | 挂靠标签 + 回顾下一步做成可点击直达；训练/记账保留在我的页「工具」组（条件 3） | 🟡 P1 |
| M3 专注条层级错 | 专注移出「习惯推进」段，独立成「执行工具」段 | 🟡 P1 |
| M4 吃药/功法两页冲突 | 我的页砍「身体养护」组 + 「模块中心」改名「工具」+ 优化习惯页「管理格子」开启入口（条件 1+2） | 🟡 P1 |
| L1 冷启动 30% 无依据 | 改成定性收口（骨架/习惯/目标都已就位），或给出明确构成 | 🟢 P2 |
| L2 首页剩余项对不上 | 概览数字口径统一，与时间轴实际数量一致 | 🟢 P2 |

## 八、落地规范

### 8.1 组件层级（复用现有 design system，不新造）
- `colors_and_type.css` 仍是唯一 token 源；本轮只调**信息架构与流转**，不改色值/字级。
- 卡片规范沿用：意图卡（`intent-card`）用于目标/习惯；工具卡（`mod`/`tool-card`）用于我的页工具；当日格（`day-cell`）用于首页快捷打卡。

### 8.2 导航规范
- 底导 5 tab 不变，激活态每页正确。
- 跨页跳转遵循「主入口唯一」：模块只从习惯页进；工具只从我的页进；回顾页的"下一步"、目标页的"挂靠"是**引用跳转**，不是新入口。

### 8.3 交互模式
- 所有「下一步 / 挂靠 / 连续天数」等跳转点，做成**可点击**（`data-href`），打通闭环，不做死文案。
- 冷启动 ②③ 步支持跳过（保留"下一步"即默认值），保证用户可 30 秒内完成。

### 8.4 实施顺序（给开发者/Design 模式的 handoff）
1. **P0**：H1（首页收敛 + 删样式预览）、H2（4 默认习惯可改）
2. **P1 · 入口改造**（本轮新增，独立成批）：
   - 我的页：砍「身体养护」组；「模块中心」改名「工具」；保留训练/记账
   - 习惯页：优化「管理格子」为清晰的「添加/启用模块」入口（让吃药/功法可发现）
   - 目标页：挂靠标签统一命名 + 可点击直达（训练/睡眠/记账/阅读）
   - 回顾页：专注独立成「执行工具」段
3. **P2**：L1（冷启动收口定性化）、L2（概览数字口径统一）
