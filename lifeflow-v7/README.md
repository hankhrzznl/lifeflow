## 一、怎么打开

### 用一键脚本（推荐）

双击 **[`启动-LifeFlow.cmd`](启动-LifeFlow.cmd)** —— 它会自动：
查端口占用 → 没有构建就先构建 → 打印本机局域网地址 → 起服务（监听 `0.0.0.0`）。

**关掉那个窗口 = 停止服务**，所以要一直开着。

| 设备 | 地址 | 布局 |
|---|---|---|
| 电脑 | http://localhost:3210 | 三栏 |
| **iPad** | http://192.168.1.4:3210 | 双栏 · **必须「添加到主屏幕」** |
| 手机 | http://192.168.1.4:3210 或 http://192.168.10.5:3210 | 单栏 + 四格底栏 |

> ⚠ **打不开时先查这个**：服务是不是停了。
> 实测踩过一次 —— 服务进程随会话被回收，**三个地址全打不开，不是网络问题**。
> 查：`Get-NetTCPConnection -LocalPort 3210 -State Listen`
> 救：双击 `启动-LifeFlow.cmd`

### iPad 必须「加到主屏」

未加主屏的网页，Safari 会在 **7 天不活跃后清掉本地数据**。
加到主屏后域名豁免 ITP（WebKit bug 209501 评论 3）。
App 内置了这个提示（首次在 iOS 上打开会弹一次）。

### 手动起服务

```powershell
cd 'C:\还原自备份\hankkk\lifeflow-unified\app-v2'
npm run start -- --hostname 0.0.0.0 --port 3210
```

### 用自己的域名（另一条路，有前提）

双击 **[`部署到Vercel.cmd`](部署到Vercel.cmd)** —— 它引导你登录 Vercel 并部署到生产环境。

⚠ **两个前提，必须先知道**：

1. **登录必须你本人做**：这台机器上的 Vercel 凭据**已失效**
   （实测 `Error: The specified token is not valid`），而 `vercel login` 要浏览器授权，AI 替不了。
2. **部署到域名 ≠ 三设备共用数据**。现在数据全在**各设备的浏览器本地**，
   部署后手机 / iPad / 电脑仍是**三份独立数据**。
   要让它们共用一份，**必须先做「跨设备同步」**（见 §五 第 1 条）。
   ⟹ **建议顺序：先接同步，再上域名** —— 否则只是把"三份数据"搬到三个网址上。

## 二、做出来的东西

### 5 个界面（不是 40 页）

| 界面 | 时间姿态 | 路由 | 治哪个痛点 | 主设备 |
|---|---|---|---|---|
| **记一笔** | 此刻 | `/log` | ① 忘了记（**最上游**） | 手机 |
| **今天** | 此刻 | `/` | ⑥ 不知道该做什么 | 手机 |
| **回看** | 刚过去 | `/past` | ④ 回看没做 · ③ 觉察不到 | iPad |
| **往后** | 往后 | `/future` | ⑧ 拆不动 | 都行（低频） |
| **工具** | — | `/tools` | ⑦ 工具互不相通 | 都行 |

### 三档布局（同一套页面，不是三个产品）

| 档 | 断点 | 布局 |
|---|---|---|
| 手机 | <768 | 单栏 + **四格底栏**（此刻/刚过去/往后/工具） |
| iPad | 768–1099 | **双栏**（内容 + 右栏）+ 左侧竖导航（fixed） |
| 电脑 | ≥1100 | **三栏**（导航 220 + 内容 + 右栏 300） |

实测列宽：iPad `345px 345px` · 电脑 `220px 672px 300px`。

### 关键实现（对照定稿）

| 定稿要求 | 落在哪 | 怎么验的 |
|---|---|---|
| **A1** 数据是一条流 | `src/lib/db.ts` 只有 `rules` + `entries` 两张业务表 | 785 条播种全部落这两张表 |
| **A5** 两类目标 | `kind: "rule"` / `"linear"` / `"period"` | 备考期 `mentions` 只存引用 |
| **A5 + §8.1** 报瓶颈不平均 | `periodSummary()` → 「现在卡在 睡眠」 | 按时期 tab 实测出现 |
| **A4'** 规则几乎不变 | 往后页不做大表单，做「系统提议 → 你确认」 | 4 条提议（含水/睡眠/时期/回看节律） |
| **A6** 记录是上游 | 记一笔常用项在最上，**点一下即记、不再确认** | e2e：点「咖啡」→ 落盘 +1 → 冷启动仍在 |
| **§9#6** 指标单点计算 | `src/lib/metrics.ts` 是唯一算指标的地方 | 页面里没有任何算术 |
| **§7** 时期只存引用 | `mentions: string[]`，**没有 parentId 字段** | 四条硬约束都守着 |
| **§3.2** 系统只提议、人按确认 | `src/components/ProposalCard.tsx` | 三个按钮：就这个 / 改一个数 / 不用 |
| **§8.2** 工具走 B | `/tools` = 标签 + 筛选视图，无独立世界 | 记账 = `tags:["记账"]` 的流 |
| **§6** iPad 必须加主屏 | `src/components/PwaRegister.tsx` + `public/sw.js` | iOS 未加主屏时弹提示 |

## 四、这一轮修掉的 6 个真问题（留痕）

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | Turbopack 构建失败 | `node_modules` 是 junction，指向项目根之外 | 真实复制进项目（589 MB / 31 秒） |
| 2 | 喝水显示 `0/30 · 0%` | **不是日期错位**（我一开始误判）：是播种每天只给 2–4 杯（500–1000ml），**永远够不到 2000ml 目标** | 播种改成 6–8 杯 |
| 3 | 情绪记录 `0/30` | 播种里**一条情绪记录都没有** | 补播（近一周不记，对应「没动」） |
| 4 | 「备考期」掉进「掉了」组 | `groupAll` 只排除了 `setting`，**没排除 `period`** —— 时期是多因素目标容器，对"每天达标"没意义 | 一并排除，走 `periodSummary()` 报瓶颈 |
| 5 | 首开就说"你 3 周没看过回看" | 播种文案**经不起核查**（第一次打开不可能有 3 周历史） | 改成基于**记录**的说法：「你已经记了 44 天」 |
| 6 | 电脑上"工具"两字折行 · iPad 无竖导航 | 竖导航栏 200px 太窄；`.shell__rail` 只在 ≥1100px 打开 | 栏宽 220 + ≥1280 才显示副标题；平板竖导航改 fixed 侧贴 |

**另修 3 处工具自身的错**（不是产品 bug，是我的检查器错）：
`eval` 不等 Promise（加 `evalAsync`）· 截断采样误判日期 · `offsetParent` 才是"可见"的正确判据。

## 六、设计口径的处置（重要）

工程根有 `canvas/modules/`（43 个模块的旧画布），它被 `gen-workorders.mjs` 当作**视觉真相源**。

**本次按 lead 的决定"重新做"，所以：**

- **画布退役**：`app-v2` 不读画布，视觉按定稿 + 线框重建
- 品牌色用 **`#002FA7`**（线上实际口径），不是画布里的 `#2458D8`
- 若要让旧工具（`gen-workorders.mjs` / `check-parity.mjs`）也认新工程，需要单独一轮改造 —— **本成品不依赖它们**
